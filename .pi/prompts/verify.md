# Verify

Use the verification skill and `.pi/laws/proof-obligations.md`.

1. Identify the important properties the change claims.
2. Match each property to evidence that can actually prove it.
3. Run the smallest deterministic checks covering those properties.
4. Expand when shared/core/high-risk behavior changed.
5. Classify failures.
6. Report PASS / FAIL / NOT RUN and anything material still unverified.

Do not treat compilation, unit tests, or a green CI signal as proof of unrelated properties.
