# .NET Aspire

Consider Aspire when a .NET solution has multiple services/resources and local orchestration/observability is becoming painful.

Use it to standardize:
- service discovery
- health checks
- OpenTelemetry/service defaults
- dependency wiring
- local containers/resources
- developer dashboard

Do not replace Docker/Kubernetes merely because Aspire exists. Use Aspire primarily to improve application composition and developer experience where it helps.
